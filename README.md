# FaustCollision

SuperCollider SynthDefs → Faust, checked sample by sample against scsynth.

FaustCollision translates a compiled SynthDef (`.scsyndef`) into a Faust program, so
that SuperCollider can be used as a specification language for any Faust target
(embedded boards, plugins, the web). It is the opposite direction of Faust's `faust2sc`.

Each SuperCollider UGen is ported to a Faust function in `translator/faust/sc.lib`, from
scsynth's C++ source rather than from the documentation. Every port has a regression
case rendered by scsynth (NRT) and by the Faust code (DawDreamer, single precision) and
compared: most match to 1e-7 or better; where they cannot (float vs scsynth's doubles,
non-causal block processing), the measured floor and its cause are recorded in the
mapping table.

## Quick start

Requirements: SuperCollider 3.13 (`sclang` and `scsynth` on the PATH), Faust 2.70
(`faust`), Python 3.12.

**1. Install** (once):

```
git clone https://github.com/vanderaalle/faustcollision.git
cd faustcollision
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python signals/make_signals.py
```

**2. Put your SynthDefs in a project folder**, anywhere, under `defs/`: one SynthDef per
`.scd` file, as SuperCollider source (not compiled `.scsyndef` files: the build runs
`sclang` on them). For example `myproject/defs/tremolo.scd`:

```supercollider
SynthDef(\tremolo, { |rate = 5, depth = 0.5|
    var in = SoundIn.ar(0);
    Out.ar(0, in * (1 - (depth * SinOsc.kr(rate).range(0, 1))));
}, metadata: (specs: (
    rate: ControlSpec(0.5, 20, \exp, 0, 5),
    depth: ControlSpec(0, 1, \lin, 0, 0.5)
)))
```

The rules:

- exactly one `Out.ar(0, ...)`: its channels become the Faust outputs;
- the audio input is `SoundIn.ar(n)`: each channel becomes a Faust input;
- every control (`|rate, depth|`) needs a range in `metadata: (specs: ...)`: each becomes
  a slider (`hslider`), with an `\exp` spec a logarithmic one.

**3. Translate** (from the faustcollision folder):

```
.venv/bin/python -m translator.build --project ../myproject
```

This writes `myproject/build/faust/tremolo.dsp`, next to copies of `sc.lib` and
`sctables.lib` that it imports: the folder is self-contained. A SynthDef that cannot be
translated gets `tremolo.error` instead, naming the reason (an unsupported UGen, a
`doneAction` other than 0, a missing spec, ...).

**4. Use the Faust** as any Faust program: `faust tremolo.dsp -o tremolo.cpp`, or one of
the `faust2...` scripts for your target (`faust2jaqt`, `faust2lv2`, `faust2daisy`, ...).
The tests compile with `-single -ftz 2` (single precision, denormals flushed).

**5. Check it against scsynth** (optional):

```
.venv/bin/python -m pytest --project=../myproject
```

This renders every SynthDef with scsynth and with Faust, over the test signals and
each control's minimum, default and maximum, and writes `myproject/report/fidelity.md`.
A SynthDef without random UGens is compared sample by sample (the tremolo above: 2e-7).
One with random UGens can only be compared statistically, and slow random modulation
(an `LFNoise1.kr(0.3)` sweeping a filter) can fail that comparison by chance: the
port cannot share scsynth's random seed. To check the rest of such a SynthDef, swap the
random source for a deterministic one while testing.

### Working on the library itself

```
.venv/bin/python -m translator.build                # examples/ and tests/cases/ -> build/
.venv/bin/python -m pytest                          # layers 1-3 -> report/fidelity.md
.venv/bin/python -m translator.census               # coverage of core UGens -> report/census.md
```

## Layout

- `translator/`: `.scsyndef` parser, `mapping.toml` (the UGen → Faust table, data only),
  code generator, sclang batch, census, `faust/sc.lib` (the ports) and `faust/sctables.lib`
  (scsynth's lookup tables, generated by `gen_tables.py`), `derive.py` (constructor-time
  structure of a few UGens).
- `tests/`: layer 1 (compiles; I/O and controls via `faust -json`), layer 2 (fidelity vs
  scsynth NRT), layer 3 (control sweeps: NaN, inf, DC, denormal runs); `tests/cases/`
  holds one regression SynthDef or more per mapping entry.
- `signals/`: test signals.
- `examples/`: example SynthDefs.
- `docs/`: `next.md` (status and next steps), `sc-findings.md`, `issues/` (upstream issue
  drafts), `faust-notes.md`, `plans/` (prepared ports not yet applied).

How the ports are made and checked (execution model, precision, tolerances from measured
floors, census): `docs/method.md`.

## Findings

Porting at this level of detail surfaces behaviour of scsynth that its documentation
does not state, some of it likely bugs: `docs/sc-findings.md` (with source references and
reproducers; drafts of upstream issues in `docs/issues/`). 36 findings so far, most of them
measured on renders, among them buffer over-reads in fifteen `.ar` UGens fed a constant or
control-rate input, an allpass that is not one (APF), and filters whose audio-rate inputs
are read from the wrong samples (BEQSuite). Faust pitfalls met along the way
(constant folding, expansion blowup, precision forms, a JIT crash): `docs/faust-notes.md`.

## Status

Covered: arithmetic and all unary/binary operators (at ar and kr, including scsynth's
nova-simd approximations at audio rate), oscillators (SinOsc, FSinOsc, SinOscFB, Saw,
Pulse, Blip, Formant, VarSaw, SyncSaw, Klang, LF*, LFGauss, Impulse, Phasor, Vibrato),
noise and random UGens (statistics), filters at ar and kr (LPF/HPF/RLPF/RHPF/BPF/BRF,
MidEQ, the BEQSuite, resonators, one/two-pole/zero, LPZ/HPZ/BPZ/BRZ, Slope, FOS, SOS,
lags, decays, Median), delays, combs, allpasses and Pluck at ar and kr, EnvGen, IEnvGen,
Line/XLine, Linen, VarLag, Ramp, dynamics, FreeVerb/FreeVerb2/GVerb, Wrap, Fold, Clip,
LinExp, InRange, InRect, Schmidt, ModDif, Select, Sanitize, DetectSilence, triggers,
panners and crossfades, Amplitude, AmpComp, MoogFF (ar), Klank, PitchShift,
LocalIn/LocalOut (feedback), server info constants; Pitch as a substitute tracker;
DynKlank, Sum3/Sum4, Hilbert, FreqShift; ambisonic and multichannel panners (PanB, PanB2,
BiPanB2, DecodeB2, PanAz); Spring, Ball, TBall; the chaos oscillators (Cusp, Quad,
LinCong, Standard, FBSine, Latoocarfian, Gbman, Henon, LorenzL, Crackle, Logistic;
statistics, their maps in double as float pairs where float32 changes the dynamics);
Gendy1/2/3 (statistics); GrainSin, GrainFM, GrainIn (the built-in Hann window; one Faust
voice per possible grain, so maxGrains <= 65); PSinGrain; Rand, IRand, LinRand, NRand,
ExpRand; `doneAction: 2` on Line, XLine and EnvGen (the program falls silent for good when
the synth would be freed); `t_` and lagged controls.

Census (`translator.census`, `report/census.md`): of the 215 core UGen classes in scope,
470 probes (one per class and rate, plus every operator); 446 pass, 1 unmapped (MoogFF.kr),
3 refused by design (T2K, Vibrato with rate variation). The 20 others are explained in
the report; most are probe artifacts: random UGens measured on few draws, chaotic maps driven by
audio-rate parameters into degenerate regimes (where double vs float and flushed denormals
decide), Crackle at its bistable default; also Blip.kr above its control-rate limit
(sc-findings 25), Hasher.kr on a -0.0 input and Pitch.kr (a substitute tracker). Unmapped
UGens are a translation error naming the class: nothing is translated by guesswork.
Excluded by design: buffers, buses, demand rate, FFT, server communication, user interface.

Known limitation: where scsynth reads an input in the constructor (an initial phase or
duty, the start of a ramp), the port uses the input's first-block value. The two differ
when that input is itself a UGen whose constructor sample differs from its first block (an
LF oscillator, for instance): the first cycle differs and, for an accumulating phase, the
offset persists.
